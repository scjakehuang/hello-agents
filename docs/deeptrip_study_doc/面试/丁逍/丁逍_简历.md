## 项目经历

### 1. 猫超 AI 导购员

**项目描述：** 天猫超市 AI 导购员是一个面向猫超购物场景的对话式智能导购系统，基于 xLangChain+TPP 图引擎构建声明式 DAG 工作流，采用 Multi-Agent 并行架构，将意图识别拆分为意图类型识别、Query 改写、需求抽取、对话生成、记忆总结 5 个子 Agent 并行执行。通过多轮对话理解用户购物意图（购买/送礼/场景/咨询/闲聊），结合商品搜索召回与 LLM 选品，生成个性化商品推荐方案，覆盖追问引导、商品推荐、场景化推荐、复购推荐、平台咨询等完整购物链路。

**核心技术：** Java、DAG、LangChain、Multi-Agent、PE、Redis Memory、模型微调

**项目亮点：**

- **DAG 分层架构设计：** 通过 xLangChain+TPP 图引擎构建声明式 DAG 编排 Multi-Agent 架构，设计公共准备层、意图识别层、意图拼装层、执行路由层、后处理层共 5 层分层架构。各模块通过注解声明依赖关系，框架自动推导 DAG 拓扑与并行度，实现了复杂购物 Agent 的可维护、可扩展的工程化落地。

- **Multi-Agent 并行拆分：** 将单体意图识别 Agent 拆分为 5 个职责单一的子 Agent（意图类型 / Query 改写 / 需求抽取 / 对话生成 / 记忆总结）并行执行，解决了单体 Agent Prompt 冗长、输出慢等问题，同时提升了输出质量和可独立迭代性。

- **Query 改写模型微调：** 针对通用大模型生成的 Query 词无法有效召回商品的问题，基于 Qwen3-30B-A3B 进行 SFT+DPO 两阶段微调。第一阶段通过 SFT 使模型掌握电商 Query 改写能力，第二阶段通过 DPO 正负样本对比学习对齐搜索引擎偏好。评测方面，构建了"LLM 多模型投票判定正确性 + 搜索工具验证有效性"的自动化离线评估链路，实现训练数据自动标注与模型效果自动评估的闭环。最终 Query 综合准确率从 57% 提升至 76.6%（+19.6pt）。

- **Redis 滑动窗口记忆 + 递归式意图总结：** 解决了多轮对话中上下文丢失和意图漂移的问题。每轮对话由记忆总结 Agent 基于"上一轮总结 + 当前输入"递归更新 ≤80 字的意图摘要，实现跨轮次意图追踪；同时在 Memory 中存储结构化元数据（resultType、keyword、intentionSummary 等），支持复购去重和意图切换检测。

- **高可用保障体系：** 关键链路（意图识别、商品推荐）配备 Plus 独立部署通道备用模型实现高可用保障；通过 CSI 绿网安全审核服务在最终输出前进行内容安全检测，拦截违规内容；通过 AB 实验开关实现单体/多 Agent 模式平滑切换和功能灰度发布，多 Agent 结果为空时自动降级到单体 Agent 兜底。

### 2. 猫超渠道化表达

**项目描述：** 渠道化表达管理猫超私域各场域的商品卡片展示。B 端素材库面向商家和运营小二，统一管理商品图片/标题/卖点等素材；C 端导购因子平台聚合离线+在线等多数据源，通过坑位-因子权重配置驱动各场域商品卡片的差异化表达，实现从素材生产到用户触达的全链路闭环。

**核心技术：** Java、Spring Boot、ODPS、Diamond、RocketMQ、iGraph、Agent WorkFlow、AI Coding

**项目亮点：**

- **Diamond 四层配置体系：** 通过因子类型定义、因子坑位绑定、权重互斥规则、加载方式映射四层配置，实现因子从定义、加载、互斥到坑位绑定的全链路配置化管理，新增因子零代码或低代码接入。

- **两阶段 Pipeline 流水线：** 参数校验 → 规则构建 → 上下文分组 → 因子查询 → 拦截处理 → 坑位填充 → 响应组装，实现 10 个 Handler 节点的有序编排，解决了多类型因子查询流程复杂、阶段间耦合度高的问题。

- **加载类型分组 + 扩展点分发：** 将因子按数据来源（DB、IC、SPI）分组构建独立执行上下文，每种加载类型通过扩展点自动路由到对应 Fetcher 执行，实现了数据源异构场景下查询逻辑的解耦与可扩展。

- **Fetcher 注册与自动发现：** 设计统一 Fetcher 注册与自动发现机制，Fetcher 通过接口方法声明负责的因子类型并自注册到对应的扩展点，无需修改框架代码，实现了因子查询能力的开闭原则。

- **AI 素材诊断工作流：** 基于状态机编排多 Agent 素材诊断工作流（判断 → 报告 → 生图 → 选图），通过原子能力抽象与多生图渠道路由实现 AI 能力热切换，串联 AB 实验形成生成→验证→采纳数据驱动闭环。

- **AI Coding 实践：** 基于项目架构与因子接入全流程沉淀结构化导购因子开发 skill，结合集团 AI Coding 插件实现需求从口述到代码的分钟级交付。

### 3. 猫超直播巡检系统

**项目描述：** 直播巡检系统是猫超直播运营工作台的核心后端模块，支持多个业务方的直播商品全链路巡检闭环。围绕"招商提报 → 定时巡检 → 异常告警"核心链路，构建价格、库存、优惠状态等多种原子巡检动作的统一管理与编排能力。

**核心技术：** Java、Spring Boot、HSF、SchedulerX、Tair、RocketMQ、SPI

**项目亮点：**

- **Pipeline 责任链 + 模板方法：** 编排设置巡检、取消巡检、执行巡检 3 条业务流水线，解决了代码耦合、难以复用与扩展的问题，实现流程步骤的可插拔和统一异常收敛。

- **"原子动作四件套"扩展范式：** Param 协议层 / Wrapper 协议转换 / Context 领域上下文 / LiveAction 业务执行，实现新增原子巡检能力的低成本迭代。

- **SchedulerX MapReduce 分治：** 基于 MapReduce 分治模型实现大批量商品并行巡检，避免了单线程串行处理万级商品导致的超时问题；Reduce 阶段触发独立汇总 Job，确保巡检与告警的故障隔离。

- **巡检-告警-触达闭环：** 巡检异常商品通过 MetaQ 消息和钉钉回告招商和运营小二，实现完整闭环。
