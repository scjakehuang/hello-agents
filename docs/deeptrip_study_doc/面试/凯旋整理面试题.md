## 一、技术基本功（40%）

> 目标：考察候选人对存储、网络、操作系统/Linux 的底层理解深度，不只是"会用"，而是"知道为什么这么设计"。
> 工程师基本技能要素的理解

### 1.1 存储

> 存储消耗的成本与性能考虑

**MySQL**

- 一条 SQL 从客户端到返回结果的完整执行路径是怎样的？（连接器→分析器→优化器→执行器→存储引擎）
- InnoDB 的 B+ 树索引和 MyISAM 有什么本质区别？为什么 InnoDB 主键推荐自增？
- 什么是覆盖索引？什么场景下索引会失效？（联合索引最左前缀、函数操作、隐式类型转换等）
- 事务隔离级别有哪几种？InnoDB 怎么解决幻读？（MVCC + Next-Key Lock）
- 做过慢 SQL 优化吗？讲一个具体案例，从发现问题到解决的全过程。
- 分库分表方案了解吗？什么时候需要分？按什么维度分？跨分片查询怎么处理？

**Redis**

- Redis 常用的数据结构有哪些？分别适合什么场景？
- Redis 缓存穿透、击穿、雪崩分别是什么？怎么解决？（布隆过滤器/互斥锁/随机过期）
- Redis 的过期策略和内存淘汰机制是什么？（惰性删除+定期删除 / 8 种淘汰策略）
- Redis 主从复制和哨兵模式的工作原理？Cluster 模式的数据分片机制？
- 用 Redis 实现分布式锁要注意什么？（SETNX + 过期时间 + Lua 解锁 + RedLock 争议）

●Redis lua脚本写过没有

**MongoDB / ES（可选，加分项）**

- MongoDB 和 MySQL 在设计理念上有什么本质不同？什么场景选 Mongo？
- ES 的倒排索引原理是什么？和 MySQL 的全文检索有什么不同？

### 1.2 网络

> 对于网络的理解到了哪一阶段
> 当你访问一个 HTTPS 网站时，从 DNS 解析到页面渲染，网络层面经历了哪些步骤？

- HTTP/1.1、HTTP/2、HTTP/3 的核心区别？（队头阻塞、多路复用、UDP-based QUIC）
- TCP 三次握手和四次挥手的过程？为什么是三次不是两次？
- TCP 的流量控制和拥塞控制是怎么做的？（滑动窗口、慢启动、拥塞避免）
- WebSocket 和 SSE（Server-Sent Events）有什么区别？分别适合什么场景？
- HTTP 代理的原理是什么？正向代理和反向代理的区别？
- 当你访问一个 HTTPS 网站时，从 DNS 解析到页面渲染，网络层面经历了哪些步骤？
- 502 / 504 错误码的含义？分别代表什么环节出了问题？

### 1.3 操作系统 / Linux

> 常用的工具要会使用
> 尽可能都说出自知道的常用命令

- 进程和线程的本质区别？协程又是什么？Go/Java 虚拟线程 分别怎么实现？
- 用户态和内核态的区别？系统调用的过程是怎样的？
- Linux 的 IO 模型：BIO、NIO、IO 多路复用（select/poll/epoll）、AIO 的区别？
- 一个 Java 应用内存持续上涨，怎么排查？（top → jstat → jmap → jstack → MAT 分析）
- CPU 使用率飙高，怎么排查是哪个进程？哪个线程？（top -H → 线程 ID → 十六进制 → jstack 定位）
- Linux 常用命令考察：怎么查端口占用？怎么查文件句柄数？怎么查磁盘 IO？

## 二、业务理解与项目复杂度（35%）

> 目标：考察候选人对复杂业务的分析能力、推进事项的方法论、以及技术之外的业务价值思考。

### 2.1 项目复杂度

项目都没有时间周期呢？能简单介绍下吗？
团队规模是怎么样的

- 讲一个你做过的**最复杂**的项目/需求。
    - 复杂在哪里？（业务逻辑多层嵌套 / 多系统协作 / 高并发 / 数据一致性要求高）
    - 你在其中承担什么角色？做了哪些关键决策？
    - 遇到的最大挑战是什么？怎么解决的？
    - 做完后效果如何？有没有坑？如何衡量？

- 一个需求从接收到上线，你的完整流程是怎样的？
    - 怎么理解需求？会主动和产品/业务方澄清什么？
    - 技术方案怎么写？会考虑哪些维度？（正常流程/异常流程/边界条件/性能/安全/可观测）
    - 上线后怎么验证效果？

- 有没有遇到过需求频繁变更的情况？你怎么处理的？对方案设计和代码结构有什么影响？

### 2.2 业务价值理解

- 你如何理解"技术服务于业务"？有没有一个案例，你的技术决策直接带来了业务价值？
- 当技术方案和业务交付时间冲突时，你怎么权衡？（举例说明）
- 你做的功能上线后，你会关注哪些指标来判断它是否"成功"？
- 你如何看待"技术债"？什么情况下值得重构，什么情况下可以先放一放？

### 2.3 多系统协作（DeepTrip 场景参考）

我们团队的实际场景供面试官参考，可据此追问：

> DeepTrip 是一个多仓库（~10 个）协作的微服务体系。一个用户对话请求经过：H5 → Nginx → dt-main（Java Filter 链 + SSE 路由转发）→ agent-b101（Python AI 编排 + LLM + 工具调用）→ 各种下游数据服务。中间涉及 Redis 状态同步、ES 日志记录、MongoDB 异常存储、ClickHouse 数据分析。

- 如果让你设计这样一个"对话全链路追踪"系统，你会考虑哪些关键信息？怎么存？
- 一个 SSE 流式接口断了，你怎么定位问题在哪一层？
- 生产环境 260+ 个接口，你想对核心链路做"流量回放验证"，你会怎么设计？

## 三、AI 理解与应用（25%）

> 目标：了解候选人对 AI 领域的关注度、工具使用习惯、以及将 AI 落地到业务中的思路。4 年经验的候选人，我们需要看到他对这波 AI 浪潮有自己的思考。

### 3.1 AI 基础理解

- 你怎么理解 LLM（大语言模型）的工作原理？Token、Context Window、Temperature 这些概念你清楚吗？
- RAG（检索增强生成）是什么？解决什么问题？在什么场景下需要 RAG？
- AI Agent 和传统的"调用 API"有什么本质不同？Agent 的核心能力是什么？（规划、工具调用、记忆、反思）
- Function Calling / Tool Use 的机制是什么？如果让你设计一个让 LLM 自动选择并调用后端接口的框架，你怎么做？
- 你关注过哪些 AI 相关的技术动态？讲讲最近让你印象比较深的一项研究或产品。
  ●为什么选择langchain

### 3.2 AI 工具使用

- 你日常开发中用 AI 工具吗？（Claude Code / Cursor / Copilot / ChatGPT 等）
    - 用得多吗？主要用来做什么？（写代码 / 查问题 / Code Review / 写文档 / 学新技术）
    - 你觉得 AI 工具对你的效率提升有多大？有什么局限性？
    - 有没有一个例子，AI 给的代码你发现有问题，你是怎么发现和修正的？

- 你觉得一个好的 Prompt 应该怎么写？有没有自己的方法论？
- 你了解 AI Coding Agent 和 AI Editor 的区别吗？（自主执行 vs 辅助补全）

●你是怎么理解agent这个词的？

### 3.3 AI 在业务中的落地

- 如果你入职后，团队希望在现有业务中引入 AI 能力，你会从哪些角度切入？
- 你认为"AI 友好的代码/架构"应该是什么样的？和传统架构有什么不同？
- 你怎么看"AI + 自动化"对工程师角色的改变？3 年后的后端工程师应该具备什么能力？
- 你了解 AI 编程工具背后的信息流动吗？（你的代码/提问去哪里了？有没有安全隐患？会怎么处理敏感信息？）
  ●我看到你说了团队提效的东西，你具体是怎么做的

## 附录 B：面试节奏建议

```
0-5 分钟：破冰，自我介绍，了解候选人当前工作内容
5-25 分钟：技术基本功（存储 10min → 网络 5min → OS/Linux 5min）
25-40 分钟：业务项目深挖（核心项目追问 + 业务价值理解）
40-55 分钟：AI 方面（理解 + 使用 + 落地思路）
55-60 分钟：开放题 + 候选人提问
```

> 注意：问题不必全问。根据候选人回答的深浅，挑重点维度深挖。如果候选人在某个方向表现出色，可以适当跳过其他方向的基础题。
