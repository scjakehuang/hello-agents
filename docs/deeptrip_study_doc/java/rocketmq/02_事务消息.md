# RocketMQ 事务消息流程

RocketMQ 事务消息用「**两阶段提交 + 状态回查**」解决「本地事务和发消息原子性」问题。

## 一、整体流程

```
   Producer 应用                       Broker
        │                                │
        │ ① 发送 Half 消息（半事务消息）   │
        ├───────────────────────────────▶│
        │                                │ 写入特殊 Topic：
        │                                │   RMQ_SYS_TRANS_HALF_TOPIC
        │ ② 返回 SEND_OK                  │ （消费者此时看不到）
        │◀───────────────────────────────┤
        │                                │
        │ ③ 执行本地事务                  │
        │    INSERT/UPDATE DB ...        │
        │    ┌──────────────┐            │
        │    │ COMMIT/ROLLBACK│           │
        │    └──────────────┘            │
        │                                │
        │ ④ 提交二次确认                   │
        │    Commit / Rollback / Unknown  │
        ├───────────────────────────────▶│
        │                                │
        │                                │ Commit → 把 Half 复制到真正
        │                                │          的 Topic，对 Consumer
        │                                │          可见
        │                                │
        │                                │ Rollback → 标记 Half 删除
        │                                │
        │                                │ Unknown / 超时 → 进入回查
        │                                │
        │                                │
        │ ⑤ ★ 状态回查（默认 60s 后，最多 15 次）│
        │   checkLocalTransaction()      │
        │◀───────────────────────────────┤
        │                                │
        │ ⑥ 查本地 DB 决定 Commit / Rollback│
        ├───────────────────────────────▶│
        │                                │
                                          ▼
                                ┌────────────────────┐
                                │   下游 Consumer     │
                                │  收到真正的消息     │
                                └────────────────────┘
```

## 二、关键点

| 阶段 | Topic | Consumer 是否可见 |
|---|---|---|
| Half 消息 | `RMQ_SYS_TRANS_HALF_TOPIC` | ❌ 不可见 |
| Commit 后 | 真实业务 Topic | ✅ 可见 |
| Rollback | （标记删除） | ❌ |

## 三、为什么需要回查？

③→④ 之间应用宕机 / 网络断开 → Broker 不知道本地事务结果 → 必须主动反查 Producer 端的本地 DB 状态。

回查由 ProducerGroup 路由到原 Producer 应用：业务实现 `TransactionListener.checkLocalTransaction(msg)`，查本地 DB 决定 Commit / Rollback。
