# RocketMQ 主从同步 + 刷盘机制

两个独立维度，组合出 4 种可靠性级别：**「同步/异步刷盘」× 「同步/异步复制」**。

## 一、整体架构

```
                        Producer
                           │
                           │ 写入
                           ▼
         ┌──────────────────────────────────────────┐
         │              Master Broker                │
         │                                            │
         │   ① PageCache（OS 内存）                   │
         │       msg → 顺序写入                       │
         │             │                              │
         │   ┌─────────┴─────────┐                   │
         │   │ 刷盘策略           │  ┌──────────┐    │
         │   │                   │  │   主从    │    │
         │   │  SYNC_FLUSH       │  │   复制    │    │
         │   │  ASYNC_FLUSH      │  │           │    │
         │   └─────────┬─────────┘  └────┬─────┘    │
         │             ▼                  │          │
         │   ② CommitLog 磁盘文件          │ ③ 网络   │
         │      (顺序写 1G/文件)           │ 同步/异步│
         │                                 ▼          │
         └──────────────────────────────────┼─────────┘
                                            │
                                            ▼
                            ┌─────────────────────────────┐
                            │       Slave Broker           │
                            │  ② PageCache → CommitLog     │
                            │  对外只读（兜底 + 读分流）    │
                            └─────────────────────────────┘
```

## 二、刷盘策略（单机维度）

```
┌──────────────────────────────────────────────────────────────┐
│  SYNC_FLUSH (同步刷盘)                                        │
│                                                                │
│  Producer ──→ PageCache ──→ fsync 到磁盘 ──→ ACK             │
│                              ↑                                 │
│                       必须等磁盘 fsync 完成                    │
│                                                                │
│  ✅ 宕机不丢   ❌ TPS 低（百级 ~ 千级）                       │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  ASYNC_FLUSH (异步刷盘，默认)                                  │
│                                                                │
│  Producer ──→ PageCache ──→ ACK                               │
│                   │                                            │
│                   └─→ FlushRealTimeService 后台线程            │
│                       每 500ms 刷一次 fsync                    │
│                                                                │
│  ✅ TPS 高（万级 ~ 十万级）   ❌ 宕机丢 PageCache 中的数据    │
└──────────────────────────────────────────────────────────────┘
```

## 三、主从复制（集群维度）

```
┌──────────────────────────────────────────────────────────────┐
│  SYNC_MASTER (同步双写)                                       │
│                                                                │
│  Master ──写本地──→ ───网络同步──→ Slave ──ACK──→ Producer  │
│                                                                │
│  ✅ 主挂数据不丢   ❌ 延迟高 + 主挂 Slave 不会自动切主         │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  ASYNC_MASTER (异步复制，默认)                                 │
│                                                                │
│  Master ──写本地──ACK──→ Producer                             │
│              │                                                 │
│              └─→ HAService 后台推送 ──→ Slave                 │
│                                                                │
│  ✅ TPS 高   ❌ 主突然宕机会丢未同步的几 ms 数据              │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  DLedger 模式 (Raft，4.5+ 推荐)                                │
│                                                                │
│      ┌──────┐                                                  │
│      │  N1  │ (Leader)                                         │
│      └──┬───┘                                                  │
│         │ Raft 半数以上 ACK 才提交                             │
│   ┌─────┴─────┐                                                │
│   ▼           ▼                                                │
│ ┌────┐     ┌────┐                                              │
│ │ N2 │     │ N3 │ (Follower)                                   │
│ └────┘     └────┘                                              │
│                                                                │
│  ✅ 自动选主 + 强一致   ❌ 至少 3 节点，资源成本高             │
└──────────────────────────────────────────────────────────────┘
```

## 四、组合选型

| 刷盘 \ 复制 | ASYNC_MASTER | SYNC_MASTER | DLedger |
|---|---|---|---|
| **ASYNC_FLUSH** | ⭐ 默认（性能优先，金融外可接受） | 兼顾（少见） | — |
| **SYNC_FLUSH** | 单机不丢，跨机可能丢 | ⭐ 金融级（不丢数据） | — |
| **N/A** | — | — | ⭐ 强一致 + 自动切主（推荐新部署） |

## 五、消息从发送到落盘"安全"的完整路径

```
Producer.send()
    │
    ▼
[Master PageCache]  ← ASYNC_FLUSH 在这里就 ACK 了（可能丢）
    │
    ▼
[Master 磁盘 fsync]  ← SYNC_FLUSH 在这里 ACK
    │
    ▼
[Slave PageCache]   ← SYNC_MASTER 在这里 ACK
    │
    ▼
[Slave 磁盘 fsync]  ← 完全不丢的最高点
```
