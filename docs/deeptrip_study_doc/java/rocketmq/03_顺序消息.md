# RocketMQ 顺序消息原理

RocketMQ 顺序消息分**全局有序**（几乎不用，Topic 只能 1 个 Queue）和**分区有序**（业务推荐）。核心：**同一个业务 Key 的消息进同一个 MessageQueue，且消费时单线程串行**。

## 一、整体流程

```
                        生产端
                ┌─────────────────────┐
                │   订单 ID = 10001    │ ──┐
                │   订单 ID = 10002    │   │
                │   订单 ID = 10001    │   │  按 orderId hash 选 Queue
                │   订单 ID = 10003    │   │  selector(orderId % queueSize)
                │   订单 ID = 10001    │   │
                └─────────────────────┘   ▼
                                  ┌─────────────────────┐
                                  │ MessageQueueSelector│
                                  └─────────────────────┘
                                          │
        ┌──────────────┬──────────────────┼──────────────┬─────────────┐
        ▼              ▼                  ▼              ▼             ▼
   ┌────────┐    ┌────────┐         ┌────────┐     ┌────────┐    ┌────────┐
   │Queue-0 │    │Queue-1 │         │Queue-2 │     │Queue-3 │    │Queue-4 │
   │10001-A │    │10002-A │         │10003-A │     │  ...   │    │  ...   │
   │10001-B │    │10002-B │         │        │     │        │    │        │
   │10001-C │    │        │         │        │     │        │    │        │
   └────────┘    └────────┘         └────────┘     └────────┘    └────────┘
       │             │                  │
       │  同 orderId 的消息 100% 进同一 Queue，且 Queue 内 FIFO
       ▼
                       消费端
   ┌─────────────────────────────────────────────────────────────┐
   │ MessageListenerOrderly （注意：不是 Concurrently）          │
   │                                                              │
   │  Consumer 对每个 MessageQueue **加锁** + **单线程**消费       │
   │                                                              │
   │  ┌────────────────┐  ┌────────────────┐                     │
   │  │ Q0 lock + 单线程│  │ Q1 lock + 单线程│  ...                │
   │  │ 10001-A → B → C│  │ 10002-A → B    │                     │
   │  └────────────────┘  └────────────────┘                     │
   └─────────────────────────────────────────────────────────────┘
```

## 二、保证顺序的三个条件（缺一不可）

| 维度 | 要求 |
|---|---|
| 发送侧 | `MessageQueueSelector` 按业务 Key（orderId/userId）路由到固定 Queue |
| 存储侧 | 同 Queue 内消息天然 FIFO（CommitLog 顺序写 + ConsumeQueue 顺序索引） |
| 消费侧 | `MessageListenerOrderly` + Broker 端 Queue 加锁，同 Queue 串行消费 |

## 三、踩坑点

消费失败返回 `SUSPEND_CURRENT_QUEUE_A_MOMENT`，Broker 会暂停该 Queue 重试，**不会跳过**——否则破坏顺序。所以顺序消息**不能用普通重试 + 死信队列**思路。

## 四、生产代码模板

```java
producer.send(msg, (mqs, msg, arg) -> {
    int idx = Math.abs(arg.hashCode()) % mqs.size();
    return mqs.get(idx);
}, orderId);
```

消费端：

```java
consumer.registerMessageListener(new MessageListenerOrderly() {
    @Override
    public ConsumeOrderlyStatus consumeMessage(
            List<MessageExt> msgs, ConsumeOrderlyContext context) {
        for (MessageExt m : msgs) {
            // 业务处理
        }
        return ConsumeOrderlyStatus.SUCCESS;
    }
});
```
